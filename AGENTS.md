# Repository Technical Documentation

## Overview

Technical documentation for the `cr-bio` Biology courses repository — directory layout, file conventions, and the publish pipeline that turns source markdown into multi-format published artifacts.

## Top-level layout

```
cr-bio/
├── course_development/   # Source of truth (back office)
│   ├── biol-1/           #   General Biology (Pelican Bay)
│   └── biol-8/           #   Anatomy & Physiology (CR Del Norte)
├── PUBLISHED/            # Generated, ready-to-share artifacts (git-ignored from cr-bio;
│                         # pushed via subtree to public per-course repos)
│   ├── biol-1/           #   → github.com/docxology/biol-1
│   └── biol-8/           #   → github.com/docxology/biol-8
├── software/             # Python automation
│   ├── src/              #   Library packages (markdown_to_pdf, format_conversion, …)
│   ├── scripts/          #   Pipeline entry points (publish_all.py, generate_all_outputs.py, …)
│   ├── tests/            #   Pytest suite (mirrors src/ layout)
│   └── docs/             #   Architecture, orchestration, quickstart docs
├── scripts/              # Repo-level shell utilities
├── publish.py            # Top-level entry point — reads publish.toml, runs the pipeline
└── publish.toml          # Pipeline configuration (formats, courses, steps)
```

`course_development/` is the only place humans edit content. `PUBLISHED/` is regenerated by `publish.py`; never edit it by hand.

## Course module layout

Each module under `course_development/biol-{1,8}/course/module-NN-name/` has the same shape:

```
module-NN-name/
├── README.md             # Student-facing module overview
├── AGENTS.md             # Technical doc for tooling
├── questions.md          # Practice questions (rendered → study-guides/)
├── keys-to-success.md    # Module study guide (rendered → study-guides/)
├── resources/            # Optional: images, datasets used by the module
└── output/               # Generated artifacts (do not commit edits here)
    ├── study-guides/     #   {questions,keys-to-success}.{md,pdf,docx}
    └── website/          #   index.html
```

Some modules omit `resources/` if they have no module-local assets; some BIOL-8 modules also include an `assignments/` subfolder for additional homework.

## File naming conventions

### Course materials

- Module folders: `module-NN-topic-words/` (zero-padded `NN`, lowercase, hyphenated words).
- Inside a module:
  - `questions.md` — practice questions for the module.
  - `keys-to-success.md` — study guide / "keys to success" notes.
- Lab files (under `course/labs/`): `lab-NN_topic-words.md`.
- Practice tests (under `course/practice_tests/`): `practice-test-NN.md`.
- Exams (under `course/exams/`): `exam-NN-topic.md`.

### Rendered artifacts

The publish pipeline writes outputs whose filename is derived from the module folder:

- `module-12-darwin-evolution/questions.md`
  → `module-12-darwin-evolution-questions.{md,pdf,docx}`
- `module-12-darwin-evolution/keys-to-success.md`
  → `module-12-darwin-evolution-keys-to-success.{md,pdf,docx}`

After rendering, files are flattened into `PUBLISHED/<course>/{homework,module_keys,labs,slides,practice_tests,dashboards,course,…}/` and additionally collected into `PUBLISHED/<course>/ALL_FILES/`.

### Software files

- Source: one package per `software/src/<module>/` with `__init__.py`, `main.py`, `utils.py`, `config.py` (when applicable).
- Tests: `software/tests/test_<module>_<unit>.py` mirroring the package layout.
- Documentation: each `software/src/<module>/` has its own `README.md` and `AGENTS.md`.

## Document authoring standards

### Lab manual identification block

All labs use the standardized `{fill:text}` notation for student identification so the PDF renderer can detect and replace it with auto-generated headers:

- **Standard pattern**: `**Name:** {fill:text} **Date:** {fill:text}` on a **single line** immediately after the course subtitle/header.
- **Behavior**: `software/src/lab_manual/` strips this exact line during PDF rendering to avoid duplicating the auto-generated PDF header, while preserving it for raw markdown readability.

## Documentation standards

### `README.md` files

- User-facing documentation for the folder.
- Overview of folder contents.
- Navigation links to related folders.
- Mermaid diagrams when structure is non-obvious.

### `AGENTS.md` files

- Technical documentation for tooling and AI agents.
- Folder structure and file naming for the folder.
- For software folders: function signatures, class APIs, dependency edges, downstream callers.
- Process and automation details specific to the folder.

Every folder under `course_development/` and `software/src/` has both a `README.md` and an `AGENTS.md`.

## The publish pipeline

`python publish.py` (configured by `publish.toml`) runs these steps:

1. **Clean** `PUBLISHED/` and source `output/` directories (optional, controlled by `publish.toml`).
2. **Generate** outputs by invoking `software/scripts/generate_all_outputs.py`, which iterates modules/labs/practice tests/exams/syllabus per course and renders requested formats (`pdf`, `docx`, `md`, optionally `html`, `txt`, `mp3`).
3. **Publish** generated files into `PUBLISHED/<course>/` via `software/scripts/publish_course.py`.
4. **Copy extras** (labs and lab dashboards) into `PUBLISHED/<course>/labs/` and `dashboards/`.
5. **Copy slides and practice tests** into both central and per-module locations.
6. **Flatten** module-nested files for direct browsing.
7. **Reorganize** into category folders (`homework/`, `module_keys/`, `labs/`, `slides/`, `practice_tests/`, …).
8. **Validate** outputs — verifies expected files exist for every module and prints a per-format summary.
9. **Git push** — commits to `cr-bio` and pushes the per-course `PUBLISHED/biol-{1,8}` subtrees to their public repos.

See `software/docs/ORCHESTRATION.md` for the detailed flow.

## Workflow recipes

### Adding a new module

1. Create `course_development/biol-X/course/module-NN-topic/`.
2. Add `README.md`, `AGENTS.md`, `questions.md`, `keys-to-success.md` (use a sibling module as template).
3. If the module has datasets/images, create `resources/` with its own `README.md` + `AGENTS.md`.
4. Run `python publish.py --dry-run` (or full publish) to verify it is picked up.

### Managing private materials

1. Place under `course_development/biol-X/private/`.
2. Document in `private/AGENTS.md`.
3. `private/` is excluded from `PUBLISHED/`; never push to student-facing repos.

### Software development

1. Add new functionality as a new package under `software/src/`.
2. Mirror the layout: `__init__.py`, `main.py`, `utils.py`, `config.py` (as needed).
3. Add tests under `software/tests/test_<module>_*.py`.
4. Write `README.md` (overview) + `AGENTS.md` (signatures, dependencies).
5. Run `cd software && uv run pytest` before opening a PR.

## Security and access

- `course_development/biol-X/private/` holds tests, answers, and accommodation data; it is **excluded** from `PUBLISHED/` and the public per-course repos.
- The Pelican Bay subtree (`course_development/biol-1/private/Pelican Bay/`) holds institution-specific PII and memos; treat as confidential.
- Never commit credentials. Canvas, OpenAI, and other API tokens belong in environment variables (see `software/docs/QUICKSTART.md`).

## Maintenance

### Regular tasks

- Keep `README.md` and `AGENTS.md` in sync with the folder when files are added or renamed.
- Run the full test suite after touching any `software/src/` module.
- Re-run `python publish.py` after content changes to refresh `PUBLISHED/` and the public repos.

### Validation

- The publish pipeline runs `software/scripts/validate_outputs.py` automatically and refuses to declare success if the expected files are missing for any in-scope module.
- Linter: `cd software && uv run ruff check .`
- Type-check: `cd software && uv run mypy src` (settings in `pyproject.toml`).

## Learned User Preferences

- Prefer direct, simple wording in exams, keys, and practice items; keep multiple-choice options clearly labeled (for example A–D); number blanks or subparts when a part groups many items.
- Keep answer keys self-contained: do not point to other files or note that the same question appears elsewhere.
- Exam-review labs and similar prep should rephrase and reorder relevant ideas without claiming how closely they match the real exam.
- Use one continuous ordered list (1–N) across `##` sections in `questions.md` and comparable worksheets unless a folder spec defines per-section numbering.
- For BIOL-1 evolution and ecology labs, favor interactive, hypothesis-driven activities over textbook recap; section titles should be plain and descriptive.
- When the user attaches an implementation plan, do not edit the plan file; work from existing todos and status updates only.

## Learned Workspace Facts

- BIOL-8 Exam 3 covers modules 11–15; keep the exam-review lab, practice tests, and syllabus dates aligned with that scope.
